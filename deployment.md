| Item | Value |
|---|---|
| OS / arch | Debian 13 (trixie), x86_64 |
| Docker | 29.8.2, overlayfs, cgroup v2 (systemd) |
| Disk | 20 GiB at `/data` (~16 GiB free) |
| Source path | `/data/mokinjay/backend` |
| Docker assets | `/data/mokinjay/docker` |
| venv | `/data/mokinjay/backend/venv` (Python 3.13.5) |
| Image | `mokinjay-sandbox:1` (422 MB) |
| Service | `mokinjay-sandbox-daemon.service`, enabled + active |
| Bind | `0.0.0.0:8100` (required: the proxy connects from outside loopback) |
| Daemon secret | `/data/mokinjay/.env`, mode 600 |
| Sessions | `/data/sessions/<session_id>`, pruned after `max_run_seconds + 1 h` |
| Admission | 2 concurrent sessions, then `503` |

The daemon disables FastAPI `/docs`, `/redoc`, `/openapi.json`; only `/health` and the
five session routes exist. `SessionStore.create` chowns `ipc/` to the container uid
when the daemon runs as root, or the kernel cannot create its socket.

### Host commands

```bash
# health (local)
curl -fsS http://127.0.0.1:8100/health

# service
sudo systemctl status mokinjay-sandbox-daemon --no-pager
sudo systemctl restart mokinjay-sandbox-daemon
sudo journalctl -u mokinjay-sandbox-daemon -n 100 --no-pager

# deploy a changed file (host has no rsync)
tar czf - -C backend app/services/sandbox/daemon/app.py \
  | ssh -p <port> <user>@<host> 'tar xzf - -C /data/mokinjay/backend'
sudo systemctl restart mokinjay-sandbox-daemon

# rebuild the image after kernel.py changes
cd /data/mokinjay && docker build -f docker/Dockerfile.sandbox -t mokinjay-sandbox:1 .
```

A machine stop ends containers; sessions are per-run, so the API opens a new one.
A resume can fall back to a fresh boot; `systemctl enable` restarts the daemon.

## 9. Measured transport limits

| Direction | Result |
|---|---|
| `POST /sessions` 31 MiB | OK |
| `POST /sessions` 32 MiB | proxy `502` **instantly**; request never reached the daemon |
| `POST /sessions` 40–95 MiB | same instant `502` — the client now chunks instead |
| `GET /outputs` 60 MiB | OK in 140 s |

**The InstaBox proxy hard-caps request bodies at 32 MiB.** Files larger than ~31 MiB
are staged by the client in 16 MiB parts:

```
POST /sessions/{id}/files?offset=<n>   raw tar bytes, chunks < 32 MiB
POST /sessions/{id}/files/finalize     extract the assembled tar into data/
```

The daemon writes chunks at their offset (a retried offset overwrites), rejects gaps,
caps the assembled tar at `STORAGE_MAX_UPLOAD_BYTES + 1 MiB`, and extracts on
finalize. A failed part deletes the remote session. The client chooses the direct
multipart create only when the tar is ≤ 31 MiB.

**Verified 2026-11-19:** a 95 MiB file was staged through the real proxy in six
16 MiB parts, finalized in 1.0 s, and a job read `99,614,720` bytes from
`/app/data/big.bin`. The effective attached-file limit is back to 95 MiB.

## 11. Rotation

- **Daemon secret:** generate `openssl rand -hex 32`, write `/data/mokinjay/.env`,
  restart the unit, set the same value as `SANDBOX_DAEMON_SECRET` on Render. Rotating
  it does not affect the B2 key or the database.
- **B2 key:** create a new application key, update both `STORAGE_S3_*` key values on
  Render, then delete the old key.
- **`LLM_ENCRYPTION_KEY`:** rotating it makes stored LLM keys, connector secrets and
  OneDrive refresh tokens undecryptable. Not a routine operation.
- **`JWT_SECRET_KEY`:** rotating it signs every user out.
- **`DATABASE_URL` password:** rotate in Supabase, update Render, redeploy.

## 12. Troubleshooting

| Symptom | Likely cause |
|---|---|
| Agent run returns `backend_unavailable`, "engine restarting" | daemon stopped, machine paused, or `409` cooldown |
| Every sandbox call `401` | `SANDBOX_DAEMON_SECRET` does not match the VM |
| `502` on create, container starts then dies | `ipc/` ownership (fixed in code) or image missing |
| `image_missing` | run `docker build -f docker/Dockerfile.sandbox -t mokinjay-sandbox:1 .` |
| Upload fails immediately | B2 key/bucket/endpoint wrong, or object > B2/JSON limits |
| Login works but API calls fail | `VITE_API_URL` missing from the built bundle, or `FRONTEND_URL` mismatch |
| `/health/db` 503 | Supabase URL wrong, project paused, or pooler mode wrong |
| First request after idle takes ~30 s | Render free spin-down; expected |
